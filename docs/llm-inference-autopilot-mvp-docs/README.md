# 大模型推理 Autopilot MVP 技术文档集

> 文档版本：v1.0  
> 基线日期：2026-08-05  
> MVP 硬件：单机、单张 NVIDIA GeForce RTX 5090（32 GB 显存）  
> MVP 部署形态：原生 Linux + Docker Compose + 独立 Host Runner  
> Agent 运行时：LangGraph  
> 状态：架构设计基线，可进入原型开发

---

## 1. 文档目标

本套文档定义一个能够在单张 RTX 5090 上跑通的“大模型推理部署与优化智能体”MVP，覆盖：

1. 硬件与软件环境检测；
2. 模型容量估算与候选配置生成；
3. 模型部署；
4. 性能测试；
5. 参数搜索；
6. 最优候选验证与证据归档；
7. 安全、审批和执行控制。

本项目不是重新实现 NVML、vLLM、EvalScope、Optuna、MLflow 或 OPA，而是在这些项目之上建设：

- 统一的领域数据模型；
- 能力包（Capability Package）；
- Tool Gateway；
- 可恢复的确定性工作流；
- 参数编译与校验；
- 实验账本；
- 可解释的配置选择；
- 可扩展的 Adapter 接口。

## 2. 核心架构结论

### 2.1 一句话结论

> 使用 LangGraph 管理可恢复流程；使用 Tool Gateway 管理工具可见性、授权和输入校验；每个环节选择一个主要外部项目，但封装成包含多个窄能力的领域能力包；AI 在实验策略层自由，底层命令、合法性、安全和回滚由确定性 Controller 控制。

### 2.2 关键设计决定 

| 编号 | 决定 |
|---|---|
| ADR-001 | 产品运行时使用 LangGraph，不将 Codex/OpenCode 魔改为产品核心 |
| ADR-002 | Codex 作为开发与代码维护助手，不直接控制生产执行 |
| ADR-003 | MVP 只支持单机单卡 RTX 5090，TP 固定为 1 |
| ADR-004 | MVP 使用 Docker Compose，不引入 Kubernetes |
| ADR-005 | 每个环节选择一个主要外部项目，但一个项目可暴露多个领域 Tool |
| ADR-006 | AI 不接收任意 Shell、Docker 参数或 `extra_args` 字典 |
| ADR-007 | Tool 输入使用判别联合、Pydantic/JSON Schema 和版本化契约 |
| ADR-008 | 长任务采用 `start → status → result/cancel` 协议 |
| ADR-009 | MLflow 负责证据存储，不负责定义“最优” |
| ADR-010 | OPA 由 Tool Gateway 强制调用，AI 无法给自己授权 |
| ADR-011 | Host Runner 与 Agent API 分离，Agent 容器不挂载 Docker Socket |
| ADR-012 | 被测试模型独占 5090，Agent 模型优先使用远程 API，支持配置 |
| ADR-013 | 所有估算结果必须标记来源与置信度，并由真机测试验证 |
| ADR-014 | 所有外部项目和容器镜像必须固定版本或 Digest，不使用未固定的 `latest` 进入可复现实验 |

## 5. 统一术语

| 术语 | 定义 |
|---|---|
| 外部项目 | NVML、vLLM、EvalScope 等被集成的开源或官方项目 |
| 能力包 | 对一个领域环节的完整封装，包含 AI Tool、内部服务、Adapter 和数据模型 |
| Agent Tool | 对 LLM 可见、语义明确、输入受限的业务动作 |
| Internal Operation | 不暴露给 AI 的参数编译、加锁、授权、重试、回滚等确定性操作 |
| Adapter | 将统一领域模型转换为具体外部项目 API、CLI 或容器配置的适配器 |
| Tool Gateway | 所有 Tool 调用必须经过的校验、策略、审批、审计和执行入口 |
| Experiment | 针对一个模型、硬件快照和工作负载目标的一次完整优化活动 |
| Trial | Experiment 中的一组具体 vLLM 参数及其一次或多次测试 |
| Candidate | 尚未完成真机验证的部署配置候选 |
| Champion | 在固定约束和证据下被选中的已验证候选 |
| Hardware Passport | 环境检测生成的硬件、软件、健康状态和风险快照 |
| WorkloadSpec | 输入/输出长度、流量模式、到达率和数据集等工作负载定义 |
| SLOSpec | TTFT、TPOT、成功率、吞吐等约束 |
| Evidence Bundle | 环境、镜像、模型 Revision、参数、原始报告和选择结论的完整证据集合 |

## 6. 最重要的边界

本 MVP **不是**：

- 多 GPU 调度平台；
- Kubernetes 推理平台；
- 多节点分布式推理系统；
- 任意模型自动兼容系统；
- 能证明全局最优的数学优化器；
- 可以自由修改客户驱动、内核和系统配置的运维机器人。

本 MVP 要证明的是：

> 在固定单机单卡环境中，系统能够安全、可重复地完成环境检测、容量规划、vLLM 部署、EvalScope 压测、Optuna 参数搜索、Top 候选复测和证据归档，并在约束条件下给出“当前已验证候选中的最佳配置”。
