# 05. 系统技术架构与数据设计

## 1. 架构目标

- 单机可部署；
- 组件职责清晰；
- Agent 与宿主机高权限执行隔离；
- 长任务可恢复；
- 每次实验可复现；
- 外部工具可替换；
- 未来可平滑迁移到多 GPU/Kubernetes；
- 不因为 MVP 简化而形成无法演进的单体脚本。

## 4. 组件职责

### 4.1 `autopilot-api`

- REST；
- LangGraph；
- Tool Gateway；
- 领域服务；
- 状态和 Job 查询；
- 不直接拥有 Docker Socket；
- 不直接访问 GPU 控制接口。

### 4.2 `autopilot-runner`

- 本地 Unix Socket 或 mTLS Localhost API；
- 执行白名单动作；
- Docker API；
- NVML；
- 文件目录管理；
- GPU Lock；
- 进程/容器 Reconciliation；
- 日志采集；
- 不包含 LLM。

### 4.3 `postgres`

建议一库多 Schema：

- `app`：业务数据；
- `langgraph`：Checkpoint；
- `optuna`：Study Storage；
- `mlflow`：Tracking Backend。

生产化后可拆库，MVP 可共用实例。

### 4.4 `mlflow`

- Run/Experiment；
- 指标；
- Artifact 元数据；
- UI；
- 不存模型权重副本，模型本身使用独立 Cache。

### 4.5 `opa`

- 策略；
- Decision；
- Decision Log；
- 不执行动作。

## 6. Host Runner API

只使用白名单动作：

```text
POST /runner/v1/environment/inspect
POST /runner/v1/deployments/start
POST /runner/v1/deployments/stop
GET  /runner/v1/deployments/{id}
POST /runner/v1/benchmarks/start
POST /runner/v1/benchmarks/{id}/cancel
GET  /runner/v1/jobs/{id}
GET  /runner/v1/jobs/{id}/artifacts
```

每个请求包含：

```json
{
  "request_id": "...",
  "idempotency_key": "...",
  "actor": "autopilot-api",
  "action": "...",
  "plan_id": "...",
  "plan_hash": "...",
  "payload": {}
}
```

Runner 再次校验：

- Action Enum；
- Plan Hash；
- 路径；
- 镜像白名单；
- 参数白名单；
- GPU Lock；
- 时间/请求/Token 限制。

## 9. Event 设计

统一事件：

```json
{
  "event_id": "...",
  "experiment_id": "...",
  "job_id": "...",
  "type": "benchmark.progress",
  "timestamp": "...",
  "sequence": 42,
  "payload": {}
}
```

主要事件：

- `graph.phase.changed`
- `approval.requested`
- `approval.decided`
- `job.queued`
- `job.started`
- `job.progress`
- `job.completed`
- `job.failed`
- `deployment.healthy`
- `trial.completed`
- `champion.proposed`

SSE 只用于展示，数据库事件是事实源。

## 10. 资源锁

### 10.1 GPU 锁

唯一资源：

```text
gpu:nvidia:0
```

锁包含：

- owner job；
- lease；
- heartbeat；
- acquired_at；
- purpose。

### 10.2 锁规则

- vLLM Deployment 持有 GPU 锁；
- EvalScope 本身不占 GPU，但依赖正在运行的 Deployment；
- 新 Trial 必须停止旧 Deployment 或进行安全替换；
- Agent 本地模型不得使用 GPU；
- Runner 重启时 Reconcile Lock 与 Docker 状态。

## 11. Job Queue

MVP 可用 PostgreSQL Queue 或单进程 Worker，不必引入 Celery/Ray。

要求：

- 单 GPU Job 串行；
- 只读查询可并行；
- Job 有租约；
- Worker 崩溃可恢复；
- 所有状态写数据库；
- 不用内存 Queue 作为唯一事实源。

分层：

```text

  < environment profile
  < capability provider profile
  < approved plan
```

配置不可由 AI 直接写文件。

重要配置：

- 数据目录；
- Token/时长预算；
- Tool 可见性；
- OPA 地址；
- 外部 Agent Model Provider；

## 13. 可观测性

MVP 至少记录：

- API 请求；
- Graph Node 耗时；
- Tool 调用；
- OPA Decision ID；
- Job 状态；
- Runner Action；
- Docker 容器；
- NVML 利用率采样；
- EvalScope 原始报告；
- MLflow Run；
- 错误分类。

Trace ID 贯穿：

```text
experiment_id → graph_run_id → tool_call_id
→ job_id → provider_job_id → mlflow_run_id
```

## 14. Docker Compose 示例骨架

```yaml
services:
  postgres:
    image: postgres:<pinned>
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U autopilot"]
    volumes:
      - postgres-data:/var/lib/postgresql/data

  opa:
    image: openpolicyagent/opa:<pinned>
    command: ["run", "--server", "/policies"]
    read_only: true
    volumes:
      - ./policies:/policies:ro

  mlflow:
    image: <internal-pinned-mlflow-image>
    depends_on:
      postgres:
        condition: service_healthy
    volumes:
      - /opt/autopilot/artifacts:/artifacts

  autopilot-api:
    image: <internal-autopilot-image>
    depends_on:
      postgres:
        condition: service_healthy
      opa:
        condition: service_started
    read_only: true
    volumes:
      - /opt/autopilot/artifacts:/artifacts
      - /opt/autopilot/runtime:/runtime
```

注意：

- API 不挂载 Docker Socket；
- Secret 使用 Docker Secret 或受限环境注入；
- 版本和 Digest 在实施时固定；
- Compose 负责控制面，不长期运行 vLLM。
