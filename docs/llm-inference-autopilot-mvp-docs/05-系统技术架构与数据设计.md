# 05. 系统技术架构与数据设计

## 1. 架构目标

- 单机可部署；
- 组件职责清晰；
- Agent 与宿主机高权限执行隔离；
- 长任务可恢复；
- 每次实验可复现；
- 外部工具可替换；
- 未来可平滑迁移到多 GPU/Kubernetes；
- 不因为 MVP 简化而形成无法演进的单体脚本。

## 4. 组件职责

### 4.1 `autopilot-api`

- REST；
- LangGraph；
- Tool Gateway；
- 领域服务；
- 状态和 Job 查询；
- 将已通过 Gateway 的长任务持久化到 PostgreSQL Lease Queue；
- 不直接拥有 Docker Socket；
- 不直接访问 GPU 控制接口；
- 不直接调用 Host Runner。

### 4.2 `autopilot-worker`

- 与 API 使用同一应用镜像，以独立进程运行；
- 使用 `FOR UPDATE SKIP LOCKED` 领取 PostgreSQL Job Lease；
- 每次执行前重新校验策略、审批、Plan Hash 和预算；
- 作为唯一挂载 Runner Unix Domain Socket 的控制面服务；
- 单 GPU 执行并发固定为 1。

### 4.3 `autopilot-runner`

- 只使用本地 Unix Domain Socket；
- 执行白名单动作；
- Docker API；
- NVML；
- 文件目录管理；
- GPU Lock；
- 进程/容器 Reconciliation；
- 日志采集；
- 不包含 LLM。

### 4.4 `postgres`

建议一库多 Schema：

- `app`：业务数据；
- `langgraph`：Checkpoint；
- `optuna`：Study Storage；
- `mlflow`：Tracking Backend。

生产化后可拆库，MVP 可共用实例。

### 4.5 `mlflow`

- Run/Experiment；
- 指标；
- Artifact 元数据；
- UI；
- 不存模型权重副本，模型本身使用独立 Cache。

### 4.6 `opa`

- 策略；
- Decision；
- Decision Log；
- 不执行动作。

## 6. Host Runner API

只使用白名单动作：

```text
POST /runner/v1/environment/inspect
POST /runner/v1/deployments/start
POST /runner/v1/deployments/stop
GET  /runner/v1/deployments/{id}
POST /runner/v1/benchmarks/start
POST /runner/v1/benchmarks/{id}/cancel
GET  /runner/v1/jobs/{id}
GET  /runner/v1/jobs/{id}/artifacts
```

每个请求包含：

```json
{
  "request_id": "...",
  "idempotency_key": "...",
  "actor": "autopilot-api",
  "action": "...",
  "plan_id": "...",
  "plan_hash": "...",
  "payload": {}
}
```

Runner 再次校验：

- Action Enum；
- Plan Hash；
- 路径；
- 镜像白名单；
- 参数白名单；
- GPU Lock；
- 时间/请求/Token 限制。

## 7. 数据库核心实体

### 7.1 `experiments`

| 字段 | 说明 |
|---|---|
| id | Experiment ID |
| status | 当前状态 |
| phase | Graph 阶段 |
| created_by | 用户 |
| requirements_json | 结构化需求 |
| hardware_passport_id | 环境快照 |
| workload_spec_id | 工作负载 |
| slo_spec_id | SLO |
| champion_id | 最终选择 |
| created_at/updated_at | 时间 |

### 7.2 `plans`

| 字段 | 说明 |
|---|---|
| id | Plan ID |
| experiment_id | 所属实验 |
| kind | environment/capacity/deployment/benchmark/optimization/verification/champion/evidence |
| schema_version | Schema |
| body_json | 完整规范化 Plan；必须包含 `execution_specification` 及其完整 `budget` |
| plan_hash | Hash |
| risk_level | 风险 |
| status | draft/approved/rejected/executed |
| approved_by | 审批人 |

### 7.3 `jobs`

| 字段 | 说明 |
|---|---|
| id | Job |
| schema_version | `job/v1` |
| experiment_id | 所属实验 |
| kind | environment/deployment/benchmark/optimization/verification/evidence |
| status | Job State |
| plan_id | 关联计划 |
| provider_job_id | 外部 ID |
| progress_json | 进度 |
| error_json | 错误 |
| result_artifact_id | 结果 |
| submitted_at/started_at/ended_at | 生命周期时间 |
| cancel_requested_at | 可持久化取消请求时间 |
| lease_schema_version/lease_owner | Lease 契约和持有者 |
| lease_acquired_at/lease_heartbeat_at/lease_expires_at | Lease 时间线 |
| lease_generation | 单调递增的 Fencing Token |
| version | 行版本 |

`(experiment_id, plan_id)` 和 `(experiment_id, result_artifact_id)` 使用组合外键。
Repository 还必须拒绝 Plan 类型与 Job 类型不一致或 Plan 尚未批准的请求。
Job 入队必须与 `idempotency_records`、`job_authorizations` 和 `job.queued` Event 在同一事务中完成；
不得创建没有授权证据的 Job。

### 7.4 `deployments`

- ID；
- Candidate；
- 容器 ID；
- Endpoint；
- 状态；
- 参数 Hash；
- 镜像 Digest；
- 模型 Revision；
- GPU ID；
- 日志 Artifact。

### 7.5 `benchmark_runs`

- Benchmark Plan；
- Deployment；
- Provider；
- 原始结果；
- 标准结果；
- Workload Hash；
- Metrics；
- 状态。

### 7.6 `optimization_trials`

- Study；
- Trial Number；
- 参数；
- 状态；
- Constraint；
- Objective；
- Benchmark Run；
- Failure Category。

### 7.7 `approvals`

- Schema 固定为 `approval/v2`；
- 组合绑定 Experiment、Plan ID、Plan Hash 和 Action；
- Requester 保存 human `UserId + Role` 快照，只允许 operator/admin；
- Approver 保存 human admin 快照，并强制与 Requester 不同；
- PostgreSQL `clock_timestamp()` 决定创建、决策和执行前过期判断；
- pending 只能迁移一次到 approved/rejected/expired，终态不可修改或删除。

### 7.8 `toolset_snapshots`

Append-only 保存每次 LLM 调用实际获得的 Tool Set：

- Tool Set ID 和 Canonical Tool Set Version；
- Experiment、Subject、Phase；
- Hardware Capability、Provider 和 Feature Flag 快照；
- 排序后的 Tool Name、Schema Version 和 Risk；
- 每次可见性策略评估的 OPA Decision ID；
- 创建时间。

Tool Set Version 由上述可信上下文和排序后的 Tool 列表计算；OPA Decision ID 只保存为证据，不进入 Version Hash。

### 7.9 `job_authorizations`

每个 Job 必须且只能有一条追加式授权证据：

- 原始 Human/Service Subject 快照；
- Action、Risk、Plan ID 和 Plan Hash；
- L2 Approval ID；
- Tool Schema、Tool Set ID/Version；
- OPA Decision ID；
- Request Hash 和服务端 Idempotency Key；
- Authorized At。

该记录通过组合外键绑定 Job、Plan、Approval、Tool Set 和 Idempotency Material。Worker 领取 Job 后读取该记录，
重新校验 Plan、预算、OPA 和 Approval；`plans.status = approved` 不能单独构成执行授权。

### 7.10 `audit_events`

Append-only：

- 时间；
- Actor；
- Action；
- Resource；
- Decision ID；
- Request ID；
- Before/After Ref；
- Result。

## 8. Artifact 设计

### 8.1 URI

```text
artifact://experiments/{experiment_id}/{category}/{artifact_id}
```

### 8.2 元数据

```json
{
  "schema_version": "artifact-metadata/v1",
  "artifact_id": "...",
  "experiment_id": "...",
  "category": "benchmark",
  "content_type": "application/json",
  "size_bytes": 0,
  "sha256": "...",
  "created_at": "...",
  "producer": {
    "component": "evalscope-adapter",
    "version": "..."
  },
  "storage_path": "relative/path"
}
```

文件使用固定逻辑路径
`experiments/{experiment_id}/{category}/{artifact_id}/payload`，payload 与 sidecar 元数据先写入同一
临时目录，再通过目录重命名原子发布。数据库只保存元数据和相对路径，不保存 Blob。

Artifact ID 不允许绑定不同内容。同一 ID、内容、Content-Type 和 Producer 完全一致时返回原元数据，
使“文件已发布但数据库事务回滚”的场景能够通过重试补登记；任何不一致都拒绝覆盖。

### 8.3 路径

```text
/opt/autopilot/
├── config/
├── models/
├── artifacts/
│   └── experiments/
├── runtime/
│   ├── locks/
│   └── sockets/
├── logs/
└── tmp/
```

所有 API 使用 Artifact ID，不使用客户端传入的绝对路径。

```json
{
  "schema_version": "job-event/v1",
  "event_id": "...",
  "experiment_id": "...",
  "job_id": "...",
  "event_type": "job.progress",
  "occurred_at": "...",
  "sequence": 42,
  "previous_status": null,
  "current_status": "running",
  "payload": {}

```

主要事件：

- `graph.phase.changed`
- `approval.requested`
- `approval.decided`
- `job.queued`
- `job.started`
- `job.progress`
- `job.cancel_requested`
- `job.lease_recovered`

- `job.failed`
- `deployment.healthy`
- `trial.completed`
- `champion.proposed`

SSE 只用于展示，数据库事件是事实源。

## 10. 资源锁

### 10.1 GPU 锁

唯一资源：

```text
gpu:nvidia:0
```

锁包含：

- owner job；
- lease；
- heartbeat；
- acquired_at；
- purpose。

### 10.2 锁规则

- vLLM Deployment 持有 GPU 锁；
- EvalScope 本身不占 GPU，但依赖正在运行的 Deployment；
- 新 Trial 必须停止旧 Deployment 或进行安全替换；
- Agent 本地模型不得使用 GPU；
- Runner 重启时 Reconcile Lock 与 Docker 状态。

## 11. Job Queue

MVP 固定使用 PostgreSQL Lease Queue 和独立单 GPU Worker，不引入 Celery/Ray。

要求：

- 单 GPU Job 串行；
- 只读查询可并行；
- Worker 使用 `FOR UPDATE SKIP LOCKED` 领取 Job；
- `queued`、`validating`、`waiting_approval` 和 `running` 的过期 Lease 均可重新领取；
- PostgreSQL `clock_timestamp()` 是 Lease 获取、Heartbeat、过期和状态落库时间的唯一权威时钟；
- 每次领取递增 `lease_generation`，Heartbeat、进度和 Worker 状态迁移必须携带当前 Fencing Token；
- 旧 Worker 即使复用同一 Worker ID，也不能用旧 Token 续租或提交终态；
- Worker 崩溃可恢复；
- Job 状态先 `flush`，对应 Event 再在同一事务追加；
- Idempotency、Event 和 Audit 记录禁止 `UPDATE`、`DELETE` 和 `TRUNCATE`；
- Provider Job ID 和取消请求持久化，重启后可继续对账和清理；
- 所有持久化契约保存 Schema Version；
- Tool Set Snapshot、Job Authorization、Idempotency、Event 和 Audit 均为追加式记录；
- 不用内存 Queue 作为唯一事实源。

## 14. Docker Compose 示例骨架

```yaml
services:
  postgres:
    image: postgres:<pinned>
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U autopilot"]
    volumes:
      - postgres-data:/var/lib/postgresql/data

  opa:
    image: openpolicyagent/opa:<pinned>
    command: ["run", "--server", "/policies"]
    read_only: true
    volumes:
      - ./policies:/policies:ro

  mlflow:
    image: <internal-pinned-mlflow-image>
    depends_on:
      postgres:
        condition: service_healthy
    volumes:
      - /opt/autopilot/artifacts:/artifacts

  autopilot-api:
    image: <internal-autopilot-image>
    depends_on:
      postgres:
        condition: service_healthy
      opa:
        condition: service_started
    read_only: true
    volumes:
      - /opt/autopilot/artifacts:/artifacts

  autopilot-worker:
    image: <internal-autopilot-image>
    depends_on:
      postgres:
        condition: service_healthy
      opa:
        condition: service_started
    read_only: true
    volumes:
      - /opt/autopilot/artifacts:/artifacts
      - /opt/autopilot/runtime/runner.sock:/runtime/runner.sock
```

注意：

- API 和 Worker 都不挂载 Docker Socket；
- 只有 Worker 挂载 Runner Socket；
- Secret 使用 Docker Secret 或受限环境注入；
- 版本和 Digest 在实施时固定；
- Compose 负责控制面，不长期运行 vLLM。
